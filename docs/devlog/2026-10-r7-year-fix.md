# 2026-10 第 7 轮：year-fix（年份不再被当成营业收入）

## 环境

- 系统：Windows 11 家庭版 中文版 10.0.26300（原生 PowerShell）
- Python：3.12.10（.venv）
- GPU：NVIDIA GeForce RTX 3050 Laptop GPU；torch 2.6.0+cu124，CUDA 可用（本轮改动为纯 Python 规则，不涉及 GPU）
- 样本：公开年报 `data/samples/public-annual-report-2024.pdf`（未入库），pymupdf 解析 + 默认切块 1646 块

## 问题与根因

r6 评审 B1：比率计算路径会把年份当营业收入，算出荒谬比率，且 verify 用同类错误抽数"印证"为 supported。

两处抽数（`core/graph/workflow.py::_try_build_calc_context`、`core/tools/verify_claim.py::_extract_labeled_amount` / `recalculate_ratio`）都用 `标签[^\d]{0,12}(数字)`：

1. 取标签后**第一个数字**，`2024年度`、`2024 年` 列标题、`（1）` 序号、`10%` 都可能被当金额。
2. 在**拼接后的全部片段**上搜索，一个块末尾的标签会吃到下一个块开头的数字。
3. 标签过宽（`收入`、`成本`、`本期`），`营业收入构成`、`占营业收入比重` 也算命中。
4. 页码回查用带千分位的数字匹配去掉千分位的文本，带千分位的数一律查不到，页码回落为 1；来源文件写成 `context`。

### 公开年报实例确认（修前）

样本第 18 页切块结果是：一个块以 `（1） 营业收入构成\n\n单位：元` 结尾，下一个块以 `2024 年\n\n2023 年` 开头。把这几个真实块交给修前的 `recalculate_ratio("毛利率", …)`，营业收入取到 **2024**，营业成本经 `成本` 宽标签取到 `（1）` 里的 **1**，算出毛利率 **99.95%**。

全量 1646 块中，同一模式还有两处把 `10%` 的 10 当成金额（`占公司营业收入或营业利润10%以上…`、`对公司净利润影响达10%以上…`）。

评审给出的合成片段 `2024年 营业收入 2024年度 1,234,567,890.12` + `营业成本 987,654,321.00`：修前算出毛利率 -48797050.25% 并判 supported。

## 修法（决策）

- 新增 `core/tools/financial_extract.py`，**计算与核验共用**一个结构化抽取函数 `extract_financial_rows`，避免两边犯同一个错误后互相印证。
- 只认"数据行"标签：`营业收入（元）`、`营业收入合计`、`营业收入为/达/：`；标签后若紧跟其他汉字（构成、比重、扣除金额…）则不是该行。前缀为 `占`、`扣除`、`非经常性损益的`、`流动` 等的命中直接排除（例如扣非净利润、流动负债合计）。
- 标签允许被 PDF 换行打断（样本里 `归属于上市公司股东的净利\n润（元）`）。
- 逐块抽取，不在拼接文本上搜索，标签不会跨块拿到下一块的年份表头。
- 数值单元格规则：
  - 4 位年份（1900–2099）在无千分位、无小数、无单位时一律不当金额；
  - `2024 年 / 2023年 / 2024 年度`、`本期 / 上年同期 / 金额` 等表头词被跳过；
  - 百分比单元格不当金额；
  - 后接 `年/月/日/页/季度/家/人…` 的数字、`第 N` 也不当金额；
  - 显式带单位的数（`2024 元`、`2,024 万元`）仍算金额。
- 按竖排表格读取：标签后的连续数值单元格依次为本期、上期，同比由本期/上期**重新计算**，不取表里的百分比。
- 单位优先级：数字后缀 > 标签内 `（万元）` > 同块内最近的 `单位：万元` 表头 > 默认元。
- 合理性检查：毛利率、净利率需在 -100%~100%，资产负债率需在 0~100%；越界就不注入写作上下文，verify 也不判 supported（返回 not_found）。宁缺勿错。
- 写作上下文的来源改为命中块的真实文件名、页码、chunk_id，并列出所用页码。
- verify 普通数字核验：`strip_claim_noise` 额外去掉完整日期（`2024年12月31日`、`2024-12-31`），`2024 年度` 整体去掉；孤立的 4 位年份不再作为待核数字。

## 新增测试

`tests/tools/test_financial_extract.py`，共 21 个用例：

- `2024` / `2023年` / `2024 年度` / 年份列表头单独出现时不得抽成营业收入；
- 年份表头后的真实金额 `1,234,567,890.12` 能抽到；
- 评审复现：毛利率得到 20.00%，不出现 -48797050；荒谬比率判 mismatch，正确比率判 supported；
- 样本第 18 页的跨块形态：抽到 545,680,493.10 / 601,286,596.33，旧的 99.95% 路径返回 None；
- 竖排表格本期/上期/同比、换行标签、扣非行排除、占比/构成/扣除金额排除；
- 万元表头、标签单位、行文"实现营业收入54,568.05万元"；
- 带单位的年份样数字仍算金额；
- 真实来源页码（无"第 1 页"回落）、越界比率不注入；
- verify 忽略孤立年份与日期。

## 结果

- 本机 pytest：`152 passed, 11 skipped, 0 failed`（11 个 skip 为原生 Windows 上的 Milvus Lite 契约）。
- 修后在样本第 7、18、19 页的真实块上抽取：营业收入本期 545,680,493.10、上期 601,286,596.33（第 7 页）；归母净利润 27,847,758.47 / 28,115,967.02。计算上下文给出营业收入同比 -9.25%、净利润同比 -0.95%，与年报表内同比列一致。
- 全量 1646 块逐块抽取，营业收入取值落在 1900–2099 的块数为 0。
- 第 18/19 页的营业成本在"分行业"表里是 `营业收入 / 营业成本 / 毛利率` 列表头加行数据的形态，本轮抽不到营业成本，因此不计算毛利率（宁缺勿错），留作后续表格结构化。
- 本轮没有重跑端到端报告生成，不提供报告层面的效果对比。

## 坑

- 本机 `%LOCALAPPDATA%\Temp\pytest-of-<用户>` 和仓库 `.pytest_cache` 本轮出现"拒绝访问"，45 个用到 tmp_path 的用例在 setup 报错（与代码无关）。没有删除这两个目录，改用 `-p no:cacheprovider --basetemp=<新临时目录>` 运行。
- PowerShell 输出中文时 `元` 偶尔显示为 `Ԫ`，这是控制台编码问题；用 Python 统计确认源码里是 U+5143。
- 本轮文件都在 Linux 上用 Python 写成 UTF-8 后再拷到本机，避免 r6 devlog 被 PowerShell 反引号转义吃掉字符的问题。
