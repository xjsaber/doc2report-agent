# 第 3 轮任务 1：去噪与 Retriever 骨架

日期：2026-10-27。基线：a724045。范围依据：parse-review-v1 的“第 3 轮必须先处理”，并按本次要求仅完成任务 1；任务 2/3 不实施。

## 要解决的问题

重复页眉页脚污染切块和 BM25；原生 Windows 不能运行 Milvus Lite，需要可替换的本地内存实现及一致的检索接口。

## 环境与决定

- 原生 Windows，仓库已有 `.venv`，实测 Python 3.12.10；CPU 执行，不使用 GPU，不下载模型。本次安装 numpy 2.5.4、rank-bm25 0.2.2。
- 去噪置于 chunk_document 入口，深拷贝后处理，不改解析原文、物理页码或表格。PyMuPDF 记录上/下各 10% 高度候选行；无坐标页面至少三行时使用首尾行。按不同页面计数，达到全部页面 30% 且至少两页才删除边缘连续匹配行。独立页码归一化，正文内部同名行不删除。清洗副本重建 sections，避免页眉污染 chunk.section。
- Retriever Protocol 保持 index_chunks/search；memory 使用 numpy 归一化点积（余弦）和 rank-bm25，按 chunk_id upsert，文档过滤先于排名。参数覆盖环境变量，Windows 默认 memory，其他平台默认 milvus。测试 fixture 强制 memory 默认，契约测试显式参数化两后端。
- hash 向量仅为默认骨架；支持注入批量 embedding callable，校验形状、有限值及维度一致性。测试使用确定性假向量。hybrid 暂为余弦加缩放 BM25，不做 RRF。分词暂为英文词/单个汉字，不引入 jieba。
- Milvus 使用懒导入、optional extra 和独立会话 collection，真实向量写入/查询走 MilvusClient，BM25 和来源元数据仍在内存；close 清理 collection。不支持重启恢复，可选 pickle 本轮未做。默认数据库目录 data/index 已被忽略。
- search_chunks、真实 embedding、RRF、UI 均未接通，未安装 streamlit/openai/sentence-transformers。

## 遇到的问题与验证

首次读取中文文档时 PowerShell 默认编码显示乱码，显式 UTF-8 重读后确认要求。
首次直接跑 pytest 时，系统旧 pytest 临时目录拒绝访问，导致 20 个 setup errors（33 passed、18 skipped），旧缓存路径也有权限警告。没有改 ACL 或删除旧目录；改用 PYTEST_ADDOPTS 指向仓库已忽略的 `.tmp/` 后恢复。

去噪模块完成后：53 passed、18 skipped、0 failed。Retriever 模块完成后及最终运行：62 passed、24 skipped、0 failed。命令：

```powershell
$env:PYTEST_ADDOPTS='--basetemp=.tmp/r3-index-final -o cache_dir=.tmp/pytest-cache'
.venv\Scripts\python.exe -m pytest -q -rs
```

去噪测试用合成 ParsedDocument 和临时目录现场生成的 PDF，覆盖 30% 阈值、低于阈值、单页保护、数字页码、正文内部同名行保留及 parse→chunk 接入。检索覆盖三个模式、排序/top_k、来源字段、空索引/查询/过滤、重复索引、更新文档归属、调用方修改隔离、空分词、非法参数与向量校验。
24 个 skip 中 7 个为 Milvus 同组参数化用例（Windows 不支持），其余 17 个为原有范围外占位。没有把 skip 当成 Milvus 已通过，没有编造召回效果或性能数字。
